## 本次更新 · What's new

- 签名校验信息优先从项目维护的 Gitee 国内镜像获取；不可用或内容无效时，继续使用现有 GitHub 加速线路和原始地址。
- 较旧的签名快照不能覆盖较新的有效缓存，包括“立即重新获取校验信息”流程。

- Signed verification info now prefers the project-maintained Gitee mirror, with the existing GitHub accelerator and direct routes as fallbacks.
- Older signed snapshots can no longer replace a newer verified cache, including during manual verification refresh.

## 安全边界 · Verification boundary

Gitee 与其他加速线路只改变传输路径。签名、文件大小和 SHA-256 仍在本机验证；镜像内容无效时会被拒绝并继续回退。

Gitee and other accelerator routes only change transport. Signature, size, and SHA-256 checks still run locally; invalid mirror content is rejected and the fallback chain continues.

## 升级 · Upgrade

直接替换旧 EXE 即可。`BrowserHarbor.json`、已安装浏览器、用户数据、Profile 和缓存不会被删除。

Replace the old EXE. `BrowserHarbor.json`, installed browsers, user data, profiles, and caches are not removed.
