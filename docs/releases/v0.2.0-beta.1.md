# Browser Harbor v0.2.0-beta.1 — Verified Edition Beta

First signed-metadata beta. It keeps the existing mirror downloader while separating release identity from transport.
首个签名元数据测试版。保留现有镜像下载方式，同时把发布身份与传输路径分开。

## 下载 · Download

Download only **BrowserHarbor-0.2.0-beta.1-x64.exe**.

只需下载 **BrowserHarbor-0.2.0-beta.1-x64.exe**。

## 可选验证资产 · Optional verification assets

These files do not need to be downloaded for normal use:

- **trusted-metadata.json**
- **trusted-metadata.sig**
- **metadata-public-key.hex**

The EXE already contains the public key and a signed bootstrap manifest. The separate files are provided only for inspection and external verification.
EXE 已内置公钥和签名启动清单；单独文件仅用于人工检查与外部验证。

## 主要变化 · Changes

- Official browser/runtime metadata is read directly from official APIs or user proxies, never from built-in accelerators.
- A verified signed manifest can be transported through domestic mirrors because its Ed25519 signature is checked locally.
- All browser, Chrome++, and Libportable installation paths now require a non-empty integrity value.
- Local packages must match the same trusted digest before extraction.
- Upstream version checks identify whether the result came from the official API or a signed release manifest.

## 兼容版 · Compatibility edition

`v0.1.0` remains frozen as the compatibility release whose metadata is not project-signed. It will not be rebuilt or replaced.
`v0.1.0` 保留为冻结的兼容版，其发布元数据没有经过本项目签名；不会重建或覆盖。

## 已知限制 · Known limitations

- The executable is not Authenticode-signed yet.
- This is a beta release intended for download and signature-fallback testing.
- The signature does not expire. The scheduled metadata workflow updates it only when upstream release information changes, without publishing another EXE.
